## 事实、取舍与工程默认值

- **事实**：本机未找到已有 Mosquitto/Docker 命令；现有后端使用 websockets 17.3。aMQTT 0.12.1 要求 websockets 15.0.1，直接混装会降级现有环境。
- **实施选择**：本机教学 Broker 使用 aMQTT 0.12.1，安装到 `.runtime/broker-venv`；后端与模拟器仅在原 `.venv` 增加 paho-mqtt 2.1.0。保留真实 MQTT 协议，不用内存事件总线冒充 Broker，也不安装 Windows 系统服务。Broker 的配置依据 [aMQTT 官方文档](https://amqtt.readthedocs.io/en/v0.12.0/references/broker_config/)，客户端按 [Paho 官方文档](https://eclipse.dev/paho/files/paho.mqtt.python/html/client.html) 使用 VERSION2 回调。
- **可替代选择**：已有 Mosquitto 时可按下方分开启动方式连接其本机端口；本轮未实测 Mosquitto。选 aMQTT 是本地环境适配，不改变主题、消息或业务语义。
- **默认参数，不是案例书制度**：模拟器每 2 秒发布一批；WebSocket 每秒发送完整当前快照；观测超过 10 秒标过期；客户端重连退避最多 10 秒。它们均不是 45 分钟巡检窗口的替代品。
- **教学边界**：Broker 仅监听 `127.0.0.1`，匿名接入，最多 16 连接。未部署公网或局域网，不宣称已具备生产鉴权、TLS 或真实硬件驱动。

## 启动、停止与复现

在 PowerShell 7 中：


首次安装主环境仍按 README 的 Python 3.11 步骤完成。Setup 幂等安装已实际执行并通过两套 `pip check`。本轮独立 Broker 环境首次创建也已执行；Setup 脚本自身的“环境不存在时创建”分支未单独做干净机器验收。

打开 `http://127.0.0.1:8000/`。启动顺序是 Broker → API（等待订阅确认）→ 模拟器。按 Ctrl+C 后按逆序停止本启动器拥有的进程；不会接管或终止其他程序。端口占用时改用：

```powershell

```

进程信息和日志保存在 `.runtime/stage01/launch-日期时间-PID/`，包含 `processes.json` 与 `stopped.json`。默认保留已有真实数据库和照片，且 `INSPECTGO_SEED_DEMO=false`，不会灌入演示现场记录。停止启动器不删除数据库、照片、日志或冻结场景。

需要手动分开启动或接已有 Broker 时，使用三个终端；`TEMP/TMP` 均先设为项目 `.runtime/tmp`，Python 均带 `-B`：


`.env.example` 记录参数名，文件不会被隐式加载；使用环境变量，或显式给 Uvicorn `--env-file`。旧 `Start.ps1` 只启动 API，不能替代完整链路启动器。

## 现场 Modify → Run → Verify

保持完整链路运行，在另一个 PowerShell 7 终端修改专用演练输入：

```powershell
Set-Location -LiteralPath 'D:\校园设施巡检与复核'
@{ 'switch-301' = @{ condition='WARNING'; metrics=@{ latency_ms=87 } } } |
  ConvertTo-Json -Depth 4 |
  Set-Content -LiteralPath '.runtime\stage01\input-overrides.json' -Encoding utf8

# 下一次发布周期自动读取文件，不重启页面。
$current = Invoke-RestMethod 'http://127.0.0.1:8000/api/current'
$current.facilities | Where-Object facility_id -eq 'switch-301' | ConvertTo-Json -Depth 6

# 恢复默认模拟观察。
'{}' | Set-Content -LiteralPath '.runtime\stage01\input-overrides.json' -Encoding utf8
```

核对 C07 的状态、87 ms、观测时间和模拟来源；开发者工具 WS 帧可看到同样内容。`config/scenarios/S1.json` 不因演练改变。无效覆盖文件会报告错误并跳过整批发布，修正后恢复；它不会静默继续宣称新值发布成功。若仅需发布一次，模拟器增加 `--once`，非法输入或连接失败返回非零退出码。

## 消息、接口与失败语义

主题固定：`nova/bb02/facility/{facility_id}/status`。消息字段固定为 `facility_id / zone_id / observed_at / source_type / availability / condition / metrics`，设施与区域来自配置。时间必须带时区；不把接收时间写成观测时间。

- `source_type` 接收 `SIMULATED` 和 `DEVICE`；当前模拟器只发 SIMULATED，DEVICE 只是接入字典，不代表已连接真实设备。
- 工程设施字典：`availability=AVAILABLE/UNAVAILABLE/UNKNOWN`，`condition=NORMAL/WARNING/FAULT`。availability 是取得的业务值，和统一证据未来的 `status=unavailable` 不同。
- `metrics` 可为最多 20 个有限数值；模拟器本轮演练仅支持 `latency_ms`。延迟若存在必须非负，缺少延迟不补造 0。
- 未收数据显示未知；链路断开或消息过期时保留最后业务值及时间，不能自动改成 FAULT。
- 按设施的 observed_at 拒绝旧消息，去重相同消息，拒绝同时间不同内容；观测超过接收时刻 5 秒的未来消息拒绝。
- 非法 JSON、过度嵌套 JSON、超 16 KiB 消息、未知设施、主题/设施不一致、区域错误和越权任务字段均拒绝。后续合法消息继续接收。
- 每个 WebSocket 客户端发送有 3 秒上限；慢客户端不会阻塞 MQTT 回调。恢复连接后发送全部 8 点快照，不用浏览器状态作为权威来源。

`GET /api/current` 与 WebSocket 共用同一内存来源，返回 `facilities_snapshot`：包含 revision、as_of、Broker 连接状态、8 点当前观察/received_at/freshness 及接收诊断。revision 重启可归零，不作为持久 run_id。健康接口 `/health` 将 API/数据库可读与 MQTT 状态分开报告，Broker 停止不伪装成设施故障。
