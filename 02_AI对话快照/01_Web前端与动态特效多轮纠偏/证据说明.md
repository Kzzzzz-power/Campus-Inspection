# 证据来源与使用说明

## 本例强调什么

本例是 **Web 前端修改与动态特效**：视觉方向、点击反馈、视图切换、弹窗反馈、加载状态、玻璃层次与空间选择。覆盖、设施状态和复核分开呈现，只作为不能被 UI 改动破坏的原有功能约束；不是本例的任务引擎开发主题。

## 建议阅读顺序

1. `说明.md`：一页过程概要。
2. `前后对照与标注.html`：三组前后对照，填写个人注释，再看视频。
3. `01/02/02b/04/04b/04c/04d`：逐张独立的真实对话截图。
4. `05/05a/05b/05c` 与 `补充证据`：运行页面、原始报告、历史录屏。
5. `对话记录.md`：逐段核对实际用户指令与 AI 答复。

## 图片处理

- 用户明确允许 Python/Pillow 精确裁切、实色遮挡和单独的对照排版；本次实际只用裁切、白底留边、标题及单处红框，**没有生成式重绘、没有遮改正文、没有重构对话气泡**。
- 全屏源图裁掉其他项目侧栏、任务标题、无关编辑器和输入栏；原始截图在用户目录保持不变，并以 SHA-256 核对副本。
- 独立证据图始终来自单张截图的连续区域；长答复分屏保留。根目录 PNG 均为至少 1280px 的整理画布。白底留边及手机图放大不增加原始信息量；原尺寸与裁切坐标见 `证据清单.json`。
- `对照与标注/` 为“编辑排版”补充，不作为未编辑的原始证据，不替代 01—05。深色原页只在视觉对照中出现，正式对话证据为浅色。
- 每张独立证据图只画一处红框；对照页留空白注释区。截图下的说明为本次整理者添加，不属于原聊天。
- 时间戳按用户要求不作为本次合格门槛；已有时间保留，不添加虚构时间。
- 本地原始副本：`D:校园设施巡检与复核.runtimeai-case-web-20261031原始图片`。未标注连续裁切：同目录 `未标注裁切`。不将含其他项目侧栏的原件放入对外案例目录。
