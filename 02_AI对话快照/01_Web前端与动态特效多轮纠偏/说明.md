# 案例 01｜Web 前端与动态特效的多轮纠偏

**范围：** 日间主题 → 按动作反馈 → 交互打磨 → 玻璃界面与空间浮层。整理于 2026-10-31；时间戳不作为本次要求。
**模块：** `frontend/app.js`、`styles.css`、`motion.js`、`model.js`、`glass.css`、`filter-pickers.js`、`index.html`。
**对应提交：** `d67506d`（日间 Web 打磨）、`d26a6c6`（玻璃界面与空间筛选）。一个提交汇集多轮工作，不逐条等同于一段对话。
**技术依据：** [日间打磨记录](../../docs/evidence/web-polish-2026-10-28/README.md)、[玻璃接入记录](../../docs/evidence/glass-ui-2026-10-29/README.md)。尚未指定最终技术文档章节号。

## 一句话结论

本例展示如何把“先看效果图”的视觉要求，逐步收敛为**与点击动作一致、能关闭、不妨碍弹窗和原有操作的 Web 动效**；名称纠正仅为补充。

## 过程概要

| 阶段 | 可核对的过程 |
| --- | --- |
| 提要求 | 要求阅读现有前端，先给效果图，再决定修改代码，检查错误前提（01）。 |
| 检查 | 比较深色原页与浅色预览，再要求点击 UI 时出现对应动态效果（02、04）。 |
| 发现问题 | 静态外观不足以说明交互。AI 修复答复另记载：暂停背景曾连带禁用弹窗按钮反馈（04b）；没有把这个根因改写为用户原话。 |
| 纠偏 | “点击相应的 ui 时出现相应的动态效果”→“继续 ui 复现”→保留页面、优化玻璃质感与空间下拉框→正式接入（04—04d）。 |
| 结果 | 留存点击反馈 13 项、日间打磨 10 项、玻璃浮层 15 项历史报告及约 28.37 秒操作录屏（旧报告误记 20.34 秒）；均为原报告/原文件，不是本次复测。 |

## 我从这件事上学到什么（整理稿，供本人核对）

效果图只能说明外观；动态效果要用同一操作下的反馈和录屏说明。刷新、筛选和打开详情应各有反馈；装饰暂停不能禁用弹窗操作。以页面保留原功能、真实反馈和可读性为约束，逐轮细化，比一次泛泛要求“更炫”更可验收。

**证据边界：** 首版预览答复已保留，但完整实施方案正文、第一次允许日间正式改码的消息未收集；不能称为无缺页会话导出。静态图不证明帧率；未补造修复前故障画面。本例不证明完整 T1—T5、3D 校园或当前版本全功能验收。
